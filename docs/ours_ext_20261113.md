## Science and schedule

`configs/realworld/ours_ext/baseline200k.yaml` is the actual saved `runs/rwcal-20261111-ours-drawer-open-pre/config.yaml`, with only the runtime `run` identity omitted. Its complete resolved science dictionary is compared with the actual run by registration, and with the checkpoint by the continuation wrapper. It preserves model, losses, compact store, calibrated inputs, episode split, batch 16, augmentation, evaluation settings, workspace anchors, seed 0, AdamW betas/decay, and W&B project `splatter4d-realworld`. It is not regenerated from today's base config. No Chamfer or ablation is added.

`continuation.yaml` layers only the explicit schedule: `steps=400000`, `original_steps=200000`, `lr_schedule=cosine_restarts`, cycles `{start:200000,end:300000,warmup:2500,peak_lr:0.00025}` and `{start:300000,end:400000,warmup:2500,peak_lr:0.00025}`. The proposed schedule has no identified flaw and is implemented as requested.

The old LR multiplier is copied with precisely the same arithmetic for every step below 200k: `(step+1)/10000` during warmup, then `r+(1-r)*0.5*(1+cos(pi*min(1,(step-10000)/190000)))`, `r=1e-5/5e-4`. A config without the new key keeps the original LambdaLR function and serialization (`lr_lambdas=[None]`), optimizer grouping and updates. The original horizon does not become 400k retroactively.

Within each restart, at elapsed `u`, LR is `min_lr + (peak-min_lr)*u/2500` for `0 <= u <= 2500`, then `min_lr+(peak-min_lr)*0.5*(1+cos(pi*(u-2500)/97500))`. LR is exactly 1e-5 at 200000, 300000 and 400000; peaks are exactly 2.5e-4 at 202500 and 302500. At the shared boundary the preceding cycle returns its annealed endpoint and the next warmup starts there. These are scheduler/global-update indices: the first update after loading 200k uses the saved minimum LR, then scheduler.step advances to 200001. Final checkpoints contain the minimum LR for the next update.

Validation rejects unknown modes, missing original horizon, gaps/overlaps, noninteger boundaries, nonpositive/overlong warmups, nonfinite or out-of-range peaks, incomplete coverage of train.steps and invalid continuation stop steps. The old cosine's stop semantics are retained.

## Evaluation protocol and label limits

All checkpoints use `scripts/evaluate_ours_length.py`, baseline snapshot, identical data/split and eval budgets (strides 1/3, max_batches=8, probe_batches=24). Outputs, metrics, panels, identity, evaluation.json, completion.json and grasp_sites.json go only in the evaluation job's own run directory. Source weights are loaded read-only, hashed before/after; no logger targets a source run. The existing `s4d/train/evaluate.py::Evaluator` runs unchanged standard diagnostics, with heldout_sets=false (no Chamfer). Its legacy obj_pos probe on real data is flange orientation, not an object/handle label; the new explicitly named probes avoid that interpretation.

Additional metrics encode camera 0 and withhold cameras 1/2 from the decoder's source feature, on held-out validation episodes:

- RGB PSNR, SSIM; LPIPS only when the package and pretrained AlexNet cache exist, without downloads. Otherwise record explicit unavailable status.
- Valid-depth L1 (metres), AbsRel, and neighboring-depth edge L1 for fine geometry. The same RGB/depth/edge metrics are restricted to the handle grasp-site ROI, with finite sample counts and null for empty support.
- Motion: rendered world displacements sampled at valid TrackEverything tracks moving >5 mm, 3D EPE (metres) and projected endpoint flow EPE (pixels). Static/padded/behind-camera/out-of-image points are excluded.
- Viewpoint invariance: cosine feature similarity for all three camera pairs on the same temporal window; deterministic 1 cm camera-x synthetic translations, render/re-encode feature consistency against the source-camera feature. This is a consistency diagnostic, not synthetic ground-truth accuracy.
- Frozen train/validation episode probes: existing standardized ridge, plus fixed 64-hidden-unit ReLU MLP, AdamW 1e-3 for 200 CPU updates, train-only input/target normalization and no validation tuning. Targets: flange EE relative to initial handle grasp-site proxy in base-frame metres; normalized gripper opening fraction; three-phase approach/grasped/post-release proxy; future EE displacement. Probe inputs are camera 0's `[past,present,present]`, preserving the three-frame architecture while keeping the future target frame unseen. R2 plus MLP RMSE/phase accuracy are reported.

ROI/handle label definition is checkpoint-independent and per episode. The store records normalized closure (0=open); take the largest valid positive closure edge as grasp, and first subsequent decrease below that edge's midpoint as release. At grasp use the most distal fifth of the stored gripper FK surface samples, by distance from the recorded flange, as the contact-region center. The palm is deliberately excluded from this estimate. Project a 35 mm physical-radius ellipse through each stored calibrated K/w2c, retain positive camera depth, and apply the same region to every window of that episode. Record all inferred grasp/release indices and 3D centers; fail explicitly if no valid closing edge exists.

**Limits / questions for scientific interpretation:** no annotated moving handle pose or calibrated aperture width is present in the saved batch contract. This implementation reports the allowed gripper-derived initial handle proxy, normalized opening fraction (not unmeasured millimetres), and heuristic phase labels, all labeled as such. A fixed initial-grasp ROI does not track the handle after it moves, so it measures initial-site detail, not an annotated moving-handle surface; refined handle tracking/annotations could be a later protocol version, applied equally to all three checkpoints. A gripper closing edge can precede contact; inspect grasp_sites.json/panels before interpreting proxy probes as contact accuracy. These do not block registration or the requested training-length experiment. Native GPU evaluation was intentionally not run under the task's CPU-only constraint.
