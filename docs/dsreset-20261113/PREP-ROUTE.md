## Admission and CPU change

Each phase-A episode declares 16 GiB GPU, 48 GiB RAM, 4 CPU threads, and 32 GiB
transient disk, with priority **-4**. The preview contains exactly 248 unique rows:
drawer success 98 + drawer failure 50 + covering failure 50 + PNP failure 50.

The controller obtains all 16 accepted MIG UUIDs from the repo host inventory.
Every launch requests exactly one `nvidia.com/gpu=MIG-...` CDI device. The
established launch wrapper acquires the LOCAL release-reservation lock, then the
REMOTE scheduler's `/home/compu/kaist/sunho/runtime/launch/admission.lock`, then
`realworld/state/launch.lock`. The shared `ops.containers.slot_guard.SOURCE`
validates fresh MIG identity, processes, declared/measured memory and growth,
per-instance max_jobs and 21.5 GiB capacity, and CPU/RAM/disk accounting. Its
`rwprep`, owner/project, GPU and memory labels are the same ones the scheduler
accounts for. No MIG is borrowed outside that accounting. A shared slice is used
only when the same guard says both jobs fit; no healthy trainer is stopped.

**Replaced CPU gate:** global load1, idle, and CPU PSI are not admission signals
for this route. They describe unrelated users (load1 ~9000) and cannot establish
our available allocation. The gate is the sum of ENFORCED `NanoCpus` quotas for
ALL our live campaign containers, including prep, plus the new job, bounded by
LIVE main `experiments/queue.yaml: hosts.remote.cpu_thread_budget`. This is stricter
than counting prep alone and matches scheduler admission. Missing/unbounded quota
fails closed. The external preflight's PSI value is explicitly neutralized only
for this new bridge; the old dispatcher's policy is untouched. GPU checks, 200 GiB
host RAM reserve, 1000 GiB campaign RAM cap, pending RAM growth, root free fraction
0.155 after transient reservations, and `/data_8T` free fraction 0.09 remain.
The locked guard repeats fresh capacity admission after potentially slow raw SHA
checks, immediately before launching. Boot launch holds remain enforced.

Ready/running/uncertain work publishes its own LIVE main priority hold under
`runs/setup/rwprep-mig-priority.d`; existing scheduler/placement admission honours
it. This independent prep queue does not write the ordinary training queue or
registry. `state/STOP` drains its workers. SSH ambiguity retains its durable launch
intent through a 600-second remote deadline plus 300-second skew allowance.
Running containers that disappear become `unknown` and block automatic retries.
Three attempts maximum; current-stage fingerprints resume completed work.
